## 固定实现

- `features.py` 只计算闭合的普通价格通道、Wilder ATR及必要质量标记；没有VP、压缩或放量强弱过滤。当前小时ATR用于止损，前一小时ATR用于匹配。
- `matching.py` 先建立共同候选U和真实父信号P，按月／UTC入场小时／事前波动层生成200个固定时间表。无放回、不放宽、不排除真实突破、不按未来成交或收益筛选；饱和层和零父信号层不消耗随机数。
- `engine.py` 在独立数据锁之后执行各自账户。规则与冻结旧P逐分钟对照一致；空仓时直接填充恒定净值区间以节约计算，持仓分钟保持原事件顺序。任何非正或非有限净值立即抛错；未平仓EOF不虚构退出。R仅允许主成本。
- `statistics.py` 使用完整1401日历日和固定200条R的同日日收益平均。两项Webb检验共享99999×46权重矩阵；月份区间共享10000×46索引；Holm族固定2，门禁U1–U7及退化、MC边界均登记输出。
- `runtime.py` 保存全部候选和时间表及生成时间后，才执行S三成本和R的200个主成本组合。逐个持久化台账；S保存分钟净值，R保留日净值及从分钟计算的风险指标。三张图只消费本批次结果，不追加模拟。首错保留STOPPED日志、已完成组合和执行器可提供的失败账户状态，禁止续跑和覆盖。

## 解锁前确定的技术实现细节

这些约定不改变计划的公式、阈值、种子、统计检验或门禁：

1. 时间统一UTC纳秒；排序和时间表SHA256使用升序小端int64原始字节。源数组由不可写的bytes支持，调用者不能就地改变上下文。时间表是离线条件对象，不要求在线前缀不变；特征和真实父信号要求前缀因果性。
2. 统计矩阵一次按登记顺序生成并保存`.npy`；另登记shape、dtype、C-order原始字节SHA256。Webb算术按4096行块执行，分块不再抽数。月均值及逐笔均值用共享月份频数乘月合计；夏普逐次取抽中月份的完整日序列，用直接`std(ddof=1)`，不以方差epsilon丢弃近似常数样本。
3. S／D每日配对，逐笔门禁按入场月／半段归属；期间累计收益按日历收益计算。持仓比例按实际持有分钟占完整日历分钟，年度暴露按持仓与年度的交集计算；不会因R成交数不同而重抽。
4. 图1随机带为实际R权益的2.5%–97.5%复制分散，另有实际中位路径和由平均日收益复合的统计指数；均不冒称市场置信区间。图2按年对比S与R的收益及成交数分散；图3显示S成本压力和D的加法月贡献。
5. 真实入口在任何数据读取前检查独立锁；只从现有BTC IS缓存及资金费文件按上下界谓词读取。核对原内容哈希、4383次结算、144个bad分钟和10个归档漏记分钟，无下载、重建或修复分支。本阶段只验证这些入口的锁和合成返回值，实际输入核验留待下一次批准。
6. `registration.json` 固定81项既有源文件／元数据的实际字节；既有27项冻结文件另外沿用其原有归一规则核验。`implementation_hashes.json` 固定本次其余所有新增文件，清单自身不做自哈希。将来只允许对本研究scope的唯一解锁行在内存还原False后核验，不能改清单消除差异。
7. 正式入口要求HEAD为实现提交的直接子提交，差异仅为独立锁False→True，且工作树完全干净、结果目录不存在。实现提交必须直接承接基线366c592。没有命令行参数、种子、抽样次数、组合或起止日期覆盖入口。
