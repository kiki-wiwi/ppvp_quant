# 实现审计的证据脚本与输出

这里是 `audit_report.md` 第 3–5 节与第 10 节所依据的审计脚本及其原始输出，按运行时的目录原样保存（只保留 `.py`、`.txt`、`.csv`、`.json`、`.md`；中间产物 `*.pkl`、`*.npy` 与 numba 缓存没有入库，需要时按各目录脚本的编号顺序重跑即可重新生成）。

`audit_brief.md` 是发给每个审计代理的统一说明：只用 BTC IS 数据与本地 1H 数据，不联网，不运行会触及 VAL / OOS / ETH 的脚本与测试，不修改仓库文件，并按实现错误、定义问题、设计选择、标注或文档问题、数据问题五类给出发现。

| 目录 | 内容 |
|---|---|
| `data1h/` | 数据与时间完整性：模式、IS 内 1H / 4H 完整性、异常小时、原始归档、引擎时间约定、前缀截断、现货预热（发现 D-1 至 D-13 的来源） |
| `ppvp1h/` | PPVP 引擎：独立重写的成交量分布与箱体、可用时刻与截断、分配假设与窗口终点的敏感性、POC 并列（P-1 至 P-8） |
| `state1h/` | 1H 状态机：独立重写的状态机、两次测试分离、carry / roll、确认形态时点、B1 兼容性（S-1 至 S-13） |
| `exec1h/` | 成交、路径与记账：独立重写的回测、资金费、盯市净值、成本分解、路径撮合器（E-1 至 E-6） |
| `verify_*` | 对应方向的对抗式复核：另一个代理尝试推翻每条发现，并用自己的脚本复算 |

脚本中的路径是当时的临时目录；在仓库根目录下运行时需把输出路径改到本地可写目录，并设置 `NUMBA_CACHE_DIR`。脚本读取数据的方式只有三种：经 `ppvp_audit.common`（数据在进入引擎前截断在 2024-01-01 之前）；只读 parquet 的模式而不读行值；或读取 IS 月份（现货为 2019 年）的本地原始归档。输出中没有 2024-01-01 及以后的任何数值，也没有 ETH 的任何数值（`data1h/s02_out.txt` 只列出了 `data/manifest.json` 的数据集名称）。
